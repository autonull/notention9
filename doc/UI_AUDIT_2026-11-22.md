## Verdict

The current surface is capable but was still doing too little to explain itself. The main
navigation was three unlabeled icons, note rows showed internal property keys as `#INTENT +4`,
deep links to notebook modes did not select the matching tab, and publishing stacked a generic
red confirm on top of the dedicated disclosure. This pass fixes those legibility and routing
defects without removing capability.

Evidence: `doc/screenshot/` (38 images), `doc/evidence/space-utilization.json`,
`doc/evidence/task-first.json`. Both audits pass after the changes.

into Connections and Settings, chat ended less than halfway down a 900px screen, and several

capability that had been reduced to a placeholder.

## Information architecture

Top-level navigation is now four views:

```
Inbox        capture + local match + recent notes
Notes        All / Tasks / Tags / Trash, with List / Board / Map / Timeline
Connections  Feed / Matches / Replies / Chat
Settings     General, AI, Network & Identity, Data & Metrics, Advanced
```

`Map`, `Timeline`, `Board`, and `Trash` are notebook modes, not peer views. `Network`, `Chat`,
and `Responses` are Connections tabs. Deep links map into those modes, so a URL and the visible
tab now agree.

## Focus hierarchy

- Header: brand and primary navigation first; transport status and settings stay quiet at the
  right.
- Inbox: capture is the first control; the local-match card is second; recent notes use two
  columns so the list does not turn into a long single-file scroll.
- Note rows: title is 14px semibold, preview 12px muted, metadata 10–11px. Internal keys are
  no longer presented as if they were hashtags.
- Network: tabs and the search/filter row come before feed cards; filter chips defer the long
  taxonomy list behind `+N more`.
- Publish: the note preview, tags/details, raw-event disclosure, and one primary publish
  action.

## Development loop

- Screenshot generation now has one implementation: `ui/test/scripts/showcase.mjs`.
  `pnpm screenshots` runs the full gallery; `pnpm screenshot <group>` refreshes one group and
  merges it. `SCREENSHOT_WORKERS` controls parallelism (defaults to the machine CPU count, capped at 8).
- A full 38-image regeneration took ~1.5 minutes with the machine default on this machine.
- `snap()` parks the pointer before capture, so hover tooltips cannot leak into evidence.
- The same script is used by the root `pnpm screenshot` command, so the two paths cannot drift.
