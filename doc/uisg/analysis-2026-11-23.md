### 2. Unassociated labels in property editor (medium, RESOLVED 2026-11-23)

- **Issue:** Key/Comparison/Value use raw `<label>` without `htmlFor`
  (`ui/src/components/editor/PropertyEditor.tsx:330,367,376`); accessible names
  fall back to placeholders. The kit `Input` already supports label association
  (`ui/src/components/ui/Input.tsx:65,79`) but is bypassed.
- **Impact:** `getByLabel` targeting fails; AT users get placeholder-derived
  names; violates the labeling contract in `doc/UI_COMPOSITION.md` and the
  one-visual-language rule.
- **Change:** pass labels through the kit `Input` (or add `htmlFor`/`id`), then
  journeys can target by label instead of fragile testIds.
- **Resolution:** `htmlFor`/`id` association added for Key, Comparison, Value
  (`PropertyEditor.tsx`); `EnhancedPropertyValueInput` gained an `id` prop
  applied alongside `testId` on every variant. Custom label styling preserved.

### 5. Harness ontology disabled matching (high, observed)

- **Issue:** `baseSettings.ontology = []` in `optimize/src/journeys.ts` is

  Local scoring then yields no matches; the v1 golden path hid this because its

- **Evidence:** matches rail showed 0 after both notes extracted roles and
  Berlin; bundle `matches.length` actual 0. Engine source:
  `ui/src/components/contexts/MatchingContext.tsx` and
  `core/src/matching/bidirectional.ts`.
- **Impact:** every match-related experiment under the harness was invalid;
  "golden path" verified navigation, not matching.
- **Change:** golden-path seed now supplies `DEFAULT_ONTOLOGY`; the journey
  asserts `matches.length === 1` from `SemanticState`. Offer text aligned to the
  request ("React developer", Berlin, TypeScript) because scoring normalizes by

- **Verified:** passing run `run_1795447295347_p10yg9v`; offer properties

## Experiment path (implemented)

`pnpm uisg to-journey <flowId> --emit-test` materializes a runnable
`ui/test/optimize/<id>.journey.ts` via `generateTestFile`; `pnpm uisg run
<flowId>` compiles, emits, builds optimize, and runs the journey;
`pnpm uisg compare <bundleA> <bundleB>` diffs status, step kinds, durations,
and failed assertions. Any modeled flow is now experimentable end-to-end.

## Limitations

- Graph steps are coarser than the registered journey (one fill step vs
  key/operator/value fills); the compiled draft omits the parameterized-route
  navigate. Compilation is a planning aid, not a replacement for the registered
  spec, until targets are fixed.
- `flow.inline-detail` is an `idea` variant (elicit seam: inline vs popup);
  untargeted by design. It needs a seam strategy proposal before synthesis.
- Drift scan covers testIds only; role+name targets were spot-checked, not
  exhaustively verified.
- Journey seeds default to an empty ontology; only golden-path opts into
  `DEFAULT_ONTOLOGY`. Match-dependent experiments must supply one.
- `matches.length` assertions assume a single relevant counterpart; grow to a
  path-based assertion when scenarios add more notes.
- Local match scores normalize over every non-marker/fact property on the
  request side; scenarios must keep request/offer property sets symmetric or
  the score falls below the 0.3 threshold.
